# Notification Module

**Version:** 1.0.0  
**Authority:** [11_Notification_Contract.md](../../../docs/implementation-contracts/11_Notification_Contract.md)  
**Status:** Active

---

## Purpose

The Notification module is responsible for delivering communications generated by platform events. It supports multiple notification channels while remaining provider-independent.

Every delivery, retry, status change, and preference lookup must pass through this module. Business modules decide **when** notifications should be sent, while the Notification module decides **how** they are delivered.

---

## Responsibilities

**Owns:**
- Notification creation and delivery lifecycle (Pending → Queued → Sending → Sent/Failed/Cancelled/Delivered/Expired)
- Delivery provider abstraction via adapters (SMTP, Twilio SMS)
- Patient communication preferences
- Message template rendering and variable interpolation
- Audit event publishing
- Retry policies and backoff calculations

**Does NOT own:**
- Decision rules for scheduling notifications (e.g. Appointment module decides when a reminder is needed)
- AI prompt generation
- Actual carrier or server connection credentials (loaded externally)

---

## Status State Machine

```
pending ──> queued ──> sending ──> sent ──> delivered (terminal)
  │            │          │         │
  ├────────────┼──────────┼─────────┼─────> failed
  │            │          │         └─────> expired (terminal)
  └────────────└──────────└───────────────> cancelled (terminal)
```

Terminal statuses accept no further transitions. Retries transition failed records back to `queued`.

## Business Rules

1. Tenant & Clinic isolation enforced on all operations.
2. Linked entities (Patient, Appointment, Conversation) are optional, but if specified must belong to the same clinic/tenant.
3. Receipents are validated before provider delivery:
   - SMS must fit E.164 formats.
   - Email must contain `@`.
4. Communication preferences (smsEnabled, emailEnabled) are respected.
5. Max 3 retries are scheduled with linear backoff (retry count * 60 seconds).
